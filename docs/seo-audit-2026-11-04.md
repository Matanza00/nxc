# NXCSOL technical SEO audit, 4 November 2026

Scope: every page in `public/`, the build that generates them (`D:\Documents\Matanza00\research\nxc2`), and the live site at https://nxcsol.com. Nothing here has been deployed. Pushing to `master` deploys to Cloudflare, so these changes go live only when you push them.

## The stack, as found

The site has no framework and is not built with React or Next.js. A Python script (`build_site.py`) renders every page in Node to static HTML. JavaScript then swaps `<main>` between pages without a full reload. Crawlers get complete HTML, including content, links, JSON-LD and meta tags, with no JavaScript needed.

| Layer | What it is |
|---|---|
| Pages | 35 prerendered HTML files (33 indexable, plus `404.html` and `/links/`, which are `noindex`) |
| Source | `research/nxc2`: `views.js`, `vs.views.js`, `seo.data.js`, `guides.data.js`, `build_site.py` |
| Hosting | Cloudflare Workers static assets (`wrangler.jsonc`), with Vercel as staging |
| Live features | `edge/worker.js` (Cloudflare) and `api/` (Vercel) |

## What was already in good shape (verified)

- Every page has a unique title, description and H1, plus a self-referencing canonical and `index, follow`.
- Open Graph and Twitter tags are on every page, and each page has its own 1200x630 share image.
- JSON-LD parses on every page: Organization, WebSite, WebPage, BreadcrumbList, Service, CreativeWork, Article or TechArticle, FAQPage, ItemList and VideoObject.
- Every image has alt text, a width and a height.
- There are no broken internal links and no heading-level skips inside page content.
- The sitemap lists every indexable page. Each `lastmod` changes only when that page's content changes.
- HTTP redirects to HTTPS and `www` redirects to the apex domain with 301s. Unknown URLs return a real 404.
- `/admin/` sends `X-Robots-Tag: noindex`.

## Recommendations that need your approval

1. **Show the hero text sooner (finding 2).** Remove the extra 0.5 s from the `.fade-in` delay for the first screen, or start the fade from a little visible instead of fully transparent. This is the biggest available LCP gain, but it changes how the page opens, so I left it alone.
2. **Load tawk.to on first interaction (finding 6).** The widget would load on the first scroll, tap or key press, or after a few seconds. This would cut phone main-thread blocking. Visitors who leave without interacting would no longer trigger the new-visitor alert.
3. **Inline the critical CSS (render blocking, est. 280 to 590 ms).** Lighthouse flags the 22 KB `site.css` as render-blocking. The fix inlines the above-the-fold rules, so each HTML file gets larger. That needs measuring before it ships.
4. **Fetch the search index on demand (finding 13).** Load it as a cached `search.json` when someone first opens search or the agent. Each page would be about 21 KB lighter.
5. **Use 301 redirects for the trailing slash (finding 12).** Do this with a Cloudflare Redirect Rule, or with `_redirects` once it has been tested on a preview deploy.

## Needs the Cloudflare dashboard

- **Managed robots.txt** (finding 1), under AI Crawl Control > Robots.txt. Decide whether AI assistants may fetch pages for a user (`ChatGPT-User`, `Perplexity-User`, `Claude-User`). Blocking them means these tools cannot open the site when someone asks about it. AI search crawlers such as `OAI-SearchBot` and `PerplexityBot` are not blocked today. The block on `Baiduspider` and `PetalBot` also affects regular search in those engines.
- **Bot challenge script.** `/cdn-cgi/challenge-platform/` is injected on every page. It causes the deprecation warnings that cap best practices at 82. If Bot Fight Mode or JavaScript detections are not needed, turn them off.
- **HSTS** is not set. Turn it on under SSL/TLS > Edge Certificates once HTTPS is confirmed everywhere.

## Also found (not SEO)

`https://nxcsol.com/api/health` returns `"agent": false, "lead": false`. On the live site the chat answers only from the page index, and the planner cannot send briefs, only open WhatsApp. To turn them on, set `GEMINI_API_KEY` and `RESEND_API_KEY` on the Worker.
